Authentication

Shakespeare AI uses Nostr NIP-98 authentication: each request is signed with your Nostr private key. For inference (chat completions and image generations) you can instead use an API key, made with NIP-98, that spends your credits.

Using with OpenAI SDK and an API key

import OpenAI from "openai"; const openai = new OpenAI({ baseURL: "https://ai.shakespeare.diy/v1", apiKey: "sk-shakespeare-...", });

Using with OpenAI SDK and NIP-98

import { NIP98Client } from "@nostrify/nostrify"; import OpenAI from "openai"; function createShakespeareAI(signer: NostrSigner): OpenAI { return new OpenAI({ baseURL: "https://ai.shakespeare.diy/v1", apiKey: "", // Not needed for NIP-98 dangerouslyAllowBrowser: true, fetch(input, init) { const client = new NIP98Client({ signer }); return client.fetch(input, init); }, }); }

Models

List Available Models

GET /v1/models

Returns a list of available models and their specifications.

Response

{ "object": "list", "data": [ { "id": "glm-4.6", "object": "model", "created": 1640995200, "owned_by": "system" }, { "id": "claude-sonnet-4.5", "object": "model", "created": 1640995200, "owned_by": "system" } ] }

Chat Completions

Create Chat Completion

POST /v1/chat/completions

Creates a completion for the chat message. Compatible with OpenAI's chat completions API.

Request Body

Parameter Type Required Description
model string Yes Model to use (glm-4.6, claude-sonnet-4.5, claude-opus-4.5)
messages array Yes Array of message objects
temperature number No Sampling temperature (0-2)
max_tokens integer No Maximum tokens to generate
stream boolean No Whether to stream responses

Example Request

{ "model": "glm-4.6", "messages": [ { "role": "user", "content": "Hello, how are you?" } ], "temperature": 0.7, "max_tokens": 150 }

Example Response

{ "id": "chatcmpl-abc123", "object": "chat.completion", "created": 1640995200, "model": "glm-4.6", "choices": [ { "index": 0, "message": { "role": "assistant", "content": "Hello! I'm doing well, thank you for asking..." }, "finish_reason": "stop" } ], "usage": { "prompt_tokens": 10, "completion_tokens": 20, "total_tokens": 30 } }

Credit Management

Note: Credit management endpoints require NIP-98 authentication, except for listing payment methods. Premium models require credits, while free models (like Tybalt) don't consume credits.

Get Credit Balance

GET /v1/credits

Retrieves the user's current credit balance.

Response

{ "object": "credits", "amount": 10.50 }

List Payment Methods

GET /v1/credits/methods

Lists the payment methods this server accepts, with the minimum purchase in dollars and the fee charged on top (0.1 is 10%). It needs no authentication. Only stripe takes a redirect_url; bitcoin says how many confirmations a payment needs before it's credited.

Response

{ "object": "list", "data": [ { "object": "payment_method", "id": "stripe", "requires_redirect_url": true }, { "object": "payment_method", "id": "lightning" }, { "object": "payment_method", "id": "bitcoin", "confirmations": 1 } ], "has_more": false, "minimum_amount": 5, "fee": 0.1 }

Add Credits

POST /v1/credits/add

Initiates a payment to add credits to the user's account. Supports Stripe, Lightning Network and onchain Bitcoin payments.

Request Body (Stripe)

{ "amount": 10.00, "method": "stripe", "redirect_url": "https://yourapp.com/payment/complete" }

Request Body (Lightning)

{ "amount": 10.00, "method": "lightning" }

Request Body (Bitcoin)

{ "amount": 10.00, "method": "bitcoin" }

A Lightning payment's url is a bolt11 invoice. A Bitcoin payment's is a BIP21 URI with a fresh address and the amount, such as bitcoin:bc1q...?amount=0.00011; it completes once the transaction confirms.

Response

{ "object": "payment", "id": "pi_abc123", "status": "pending", "amount": 10.00, "fee": 1.00, "total": 11.00, "method": "stripe", "description": "Credit purchase via Stripe", "url": "https://checkout.stripe.com/pay/cs_...", "created_at": 1640995200, "expires_at": 1640999800 }

Check Payment Status

GET /v1/credits/payments/{payment_id}

Checks the status of a payment. Payments are completed automatically once paid: by Stripe's webhook, or by checking the Lightning invoice or the Bitcoin address.

List Payments

GET /v1/credits/payments

Retrieves a paginated list of payments for the user.

Query Parameters

Parameter Type Description
limit integer Maximum number of payments to return (default: 20, max: 100)
starting_after string Payment ID for pagination
status string Filter by status: pending, completed, failed, expired
method string Filter by method: stripe, lightning, bitcoin

API Keys

Note: API keys work only for /v1/chat/completions and /v1/images/generations, sent as Authorization: Bearer <key>. Managing keys, and everything else, requires NIP-98, so a leaked key can only spend up to its limit.

A key spends the credits of the Nostr account that made it. Its generations appear in /v1/credits/generations with its api_key_id. An account can have up to 100 keys that haven't been revoked.

Create API Key

POST /v1/keys

Creates a key. Every field is optional, and the body may be empty. The response's key is shown only this once: store it safely.

Request Body

Parameter Type Description
name string A name for the key, up to 100 characters
limit number | null The most credits the key may spend (default: no limit)
limit_reset string | null When the limit starts again: daily, weekly or monthly (at midnight UTC, Mondays, or the 1st). Without one, the limit is for the key's lifetime.
expires_at integer | null When the key stops working, in Unix seconds

Example Response

{ "object": "api_key", "id": "key_3f9a1c0b7e2d4a6f8b1c2d3e", "name": "My bot", "label": "sk-shakespeare-1a2b...9f8e", "disabled": false, "limit": 5.0, "limit_reset": "monthly", "limit_remaining": 5.0, "usage": 0.0, "usage_daily": 0.0, "usage_weekly": 0.0, "usage_monthly": 0.0, "created_at": 1795100645, "updated_at": 1795100645, "expires_at": null, "revoked_at": null, "key": "sk-shakespeare-1a2b(56 more hex characters)9f8e" }

List API Keys

GET /v1/keys

Lists your keys, newest first, revoked ones included, with limit and starting_after for pagination as for payments. Each is as above, without key.

Get API Key

GET /v1/keys/{key_id}

Update API Key

PATCH /v1/keys/{key_id}

Changes any of name, limit, limit_reset, expires_at and disabled (true or false). Fields left out stay as they are; null clears a limit, its reset or an expiry.

Revoke API Key

DELETE /v1/keys/{key_id}

Revokes a key permanently. It stays in the list, with revoked_at set, and can't be changed or used again.

API Key Error Codes

  • invalid_api_key (401) - The key doesn't exist
  • api_key_disabled, api_key_expired, api_key_revoked (401) - The key can't be used now
  • key_limit_exceeded (429) - The key has reached its spending limit
  • nip98_required (401) - An API key was used for something other than inference
  • api_key_not_found (404) - No such key of yours
  • too_many_api_keys - Revoke a key to make another

Error Handling

Shakespeare AI uses standard HTTP status codes and returns errors in OpenAI-compatible format.

Common Error Codes

HTTP Status Error Code Description
401 unauthorized Invalid or missing NIP-98 authentication
400 invalid_request_error Invalid request format or parameters
429 insufficient_quota Insufficient credits for premium models
500 api_error Internal server or upstream provider error

Error Response Format

{ "error": { "type": "insufficient_quota", "code": "insufficient_credits", "message": "You have insufficient credits for this request", "param": null } }

Credit Management Error Codes

  • minimum_amount_not_met - Payment amount below minimum threshold
  • unsupported_method - Payment method not supported
  • missing_required_parameter - Required parameter missing
  • payment_not_found - Payment ID not found
  • payment_expired - Payment has expired
